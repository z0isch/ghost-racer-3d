# Retire coins for a checkpoint ladder, and let income ghosts run Runs

Status: proposed

`0001` made a Run a fixed time budget and left every ghost consumer pointed at a recording that had grown from one short lap into a long, multi-wrap line — an open question it deliberately did not answer. This answers it, and in doing so replaces what the money in this game *is*. **Coins are retired**: nothing stands off the road to be collected for cash, and the coin field goes with them. **Checkpoints pay instead**, on a **checkpoint ladder** — the *n*th checkpoint taken in a Run pays *n* times the circuit's base checkpoint value, counted from the Run's first checkpoint and running straight through every wrap without resetting, so a Run of 45 checkpoints earns 1035 base values and its last checkpoint alone pays 45. A new pickup, the **clock**, stands off the racing line and pays in seconds added to the Run's time budget rather than in money. And an **income ghost now runs Runs rather than passes of the track**: it replays the record Run's recording end to end, paying the same ladder that Run paid, Timeouts, pops back to the start line, and begins the ladder again from its first rung.

The ladder exists because a fixed Run duration had quietly made the earn rate decorative. A Timeout always lands with the Run clock at the circuit's configured duration, so the denominator was a constant and the record ranked Runs identically to raw earnings — a rate in name only. Paying checkpoints a flat amount would not have fixed that and would have made things worse: checkpoints are mandatory and ordered, so a flat payout makes the earn rate a linear function of average speed and nothing else, and the game becomes lap time with a dollar sign. The ladder restores a rate that responds to both things a Run can vary. With *N* checkpoints taken over *T* seconds the rate is `base·N(N+1)/(2T)`, strictly increasing in *N* at a fixed *T* and strictly increasing in *T* at a fixed checkpoint interval: **a longer Run and a better-driven Run each necessarily earn more per second.** Growth is linear rather than geometric because under geometric growth the rate goes exponential in Run length — doubling a Run's duration raises its rate to a power rather than multiplying it — which makes Runs of different lengths incomparable and turns the record into a measure of how many clocks were grabbed, with driving as a rounding error.

The base checkpoint value is one number per circuit and deliberately **not** per-checkpoint. A checkpoint cannot be skipped, so its value can never be a decision; making a hairpin's checkpoint pay double would be a payout schedule dressed as a mechanic. Everything that is a decision has to be optional, which is what the clock is for, and the clock is now the only thing in the game standing off the racing line. It is the mirror of what a coin was — a coin sat off the line and added to the numerator of the earn rate, a clock sits off the line and adds to the denominator — and the question it asks is whether the detour is worth the seconds it buys.

**A clock is not restored on a wrap**, and this is load-bearing rather than a nicety. The clock field is per-Run where the boost and hazard fields are per-wrap, and since the earn rate grows without bound in Run length, an indefinitely extendable Run would have an unbounded record. A circuit's authored clock seconds are therefore the ceiling on how long its best Run can be and, through that, the ceiling on its record. The wrap otherwise becomes what the countdown used to be: the boost and hazard fields are placed along one wrap's worth of the ghost line and re-rolled at every wrap, so a long Run is not one live wrap followed by an empty circuit.

Income ghosts run Runs because a ladder indexed on the ordinal within a Run has nothing to multiply for a thing that runs forever. Restarting the ladder each pass of the track would pay the worst rungs forever; letting it grow forever diverges. Replaying the whole recording as a Run resolves it exactly, and buys a property the game has never had: **income is precisely the record earn rate, per ghost**, so the two dollars-per-second numbers in the game agree by construction. It also makes the recording's end-to-start pop honest — the recording ends mid-corner at a Timeout and resumes at the start line, which is a Timeout followed by a Countdown, exactly what a Run does. The ghosts are seated as they are today, the *i*th a fraction *i*/*N* through the recording, which spaces them evenly **through the Run** and not around the track: over a *W*-wrap recording that lands ghost *i* near track fraction `(i·W/N) mod 1`, so when *N* and *W* share a factor the ghosts clump into a knot instead of ringing the circuit. That is accepted deliberately. Even spacing through the Run is what staggers the Timeouts, so the field never pops back to the line all at once — the alternative buys a prettier formation at the cost of a synchronised teleport of every car on the circuit — and the clump is a resonance between two numbers rather than a property of a circuit, re-rolling whenever either changes.

What it touches: `GhostLine` gains the sample index of each wrap, written by the run director which already knows the moment and read by the boost and hazard fields for per-wrap placement — income does not need it. `CoinField` and `CoinOrigins` are deleted and a `ClockField` takes the coin field's shape, including its place in the circuit loadout, where `coin_count` becomes `clock_count`. `IncomeGhostSweep` loses the coin sweep entirely: a recording's checkpoint crossings are fully determined by the recording, so they are precomputed once at reseat and the ghost pays rung *n* on crossing *n*, which is cheaper than a swept test and keeps the pickup popups standing where the money was earned. Saved ghost lines have no wrap array; a line without one is treated as a circuit that has never been driven, and clears itself the first time someone sets a record.

Two costs are accepted rather than solved. The shop loses its only purchase that changed the numerator — buying a coin used to raise income the instant it was bought, and nothing now raises income except buying income ghosts, or buying clocks and then driving a longer Run that sets a higher record. That is a slower loop, and it requires driving, which may be a feature. And with coins gone the game is a time trial: the clock is the whole of its decision layer, one decision type repeated, where the driving used to be held against a field of money lying off the line.

Open, and deliberately not decided here: whether the Run clock should start at countdown-zero or at the first checkpoint taken, which decides how much the standing start drags the record; whether the boost and hazard fields should be *re-rolled* at every wrap or merely restored to where they stood, since re-rolling means a wrap cannot be learned; and what colour a clock's pickup popup is, which cannot be green — green is the purse's, and a clock is not money.
